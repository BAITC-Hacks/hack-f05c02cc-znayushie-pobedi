# EKT — каталог и модуль поиска для backend

**Версия контракта: 1.0.** Это отдельный комплект для интеграции, а не копия файлов с компьютера участника.
Внутри — 40 нормализованных товаров, исходные снимки, Python-модуль, необязательный FastAPI-router, примеры и тесты.
Ядро работает без внешних библиотек, сетевых запросов и API-ключей. Python 3.10+.
Это **офлайн-поиск и предварительное сравнение**, а не завершённый RAG/чат или производственная система закупок.

## 1. Быстрый запуск без сервера

Распаковать архив и открыть терминал в папке `ekt_backend_handoff`:

```bash
python3 demo.py
python3 demo.py "Legrand 125A"
python3 -m unittest discover -s tests -v
```

Если `python` уже указывает на Python 3 в виртуальном окружении, можно использовать `python` вместо `python3`.
Без дополнительных зависимостей тесты HTTP-адаптера будут пропущены; тесты ядра работают.
Проверенный результат полного набора — в `TEST_RESULTS.txt`. Системы пользователя и партнёра отдельно не проверялись.

## 2. Что перенести в проект backend

Достаточно **всей папки `ekt_catalog/`**, включая `data/products.normalized.json`.
Старые `ai.py`, `search.py`, `analogs.py`, `api.py` из учебных шагов этому модулю НЕ нужны.
Не переносить `.env`, ключи, `venv/` или `.venv/`.

```python
from ekt_catalog import CatalogService

catalog = CatalogService()  # создать один экземпляр на процесс

result = catalog.search_products("Legrand 160 ампер")
product = catalog.get_product_detail(515291)
stock = catalog.check_stock(515291, quantity=5, store_id=13)
candidates = catalog.find_analogs(515290)
```

Путь к данным по умолчанию вычисляется относительно файла модуля, а не текущей папки терминала.
Собственный нормализованный файл: `CatalogService('/absolute/path/products.normalized.json')`.
Каталог читается один раз; после обновления данных создать новый экземпляр/перезапустить процесс.
Возвращаются копии данных — изменение ответа не меняет каталог в памяти.

Для коротких вызовов экспортированы и функции с такими же именами:

```python
from ekt_catalog import search_products, get_product_detail, check_stock, find_analogs
result = search_products("200300285_")
```

## 3. Интерфейс поиска

```python
catalog.search_products(
    query="",
    filters={
        "brand": "Legrand",
        "current_a": 160,
        "phase_count": 3,
        "product_type": "circuit_breaker",
    },
    limit=10,
    include_uncertain=False,
)
```

Поддерживаемые поля `filters`:

| Поле | Смысл |
|---|---|
| `id` | ID товара |
| `article` | Точный внутренний артикул, артикул поставщика или числовая ссылка в начале имени |
| `brand` | Бренд из имени/свойств, без догадки по URL |
| `series` | Распознанная серия DRX |
| `product_type` | `circuit_breaker`, `rcbo`, `relay`, `box`, `lighting` |
| `current_a` | Номинальный ток; в текущем парсере только автомат/дифавтомат |
| `phase_count` | Количество фаз, когда оно явно указано |
| `poles` | Количество полюсов, НЕ количество фаз |
| `breaking_capacity_ka` | Указанная отключающая способность |
| `voltage_v` | Указанное номинальное напряжение |
| `max_price` | Верхний предел числовой цены из снимка, без пересчёта валют |

Для совместимости с предыдущим `understand_query()` есть алиасы:
`current → current_a`, `phases → phase_count`, `type → product_type`,
`product_id → id`, `breaking_capacity → breaking_capacity_ka`, `voltage → voltage_v`.
`product_type='автомат'` преобразуется в `circuit_breaker`. Значения `None` пропускаются.
Неизвестные ключи вызывают `ValueError`, а не молча игнорируются.

**Прямая передача результата уже работающего AI:**

```python
filters = understand_query(user_message)  # функция из вашего AI-слоя, не из этого архива
result = catalog.search_products(filters=filters)
```

Это предпочтительнее обратной склейки структурированных характеристик в текст.
Для сложных фраз сначала извлекать параметры через собственный AI-слой и валидировать их.
Ядро не делает вызовы OpenAI/NVIDIA, не обучает модель и не создаёт embeddings.

### Поиск строкой

Работают простые запросы `Legrand 160A`, `легранд 160 ампер`, `трехфазный автомат Legrand 160А`,
артикулы `200300285_`, `027228`, ID `515291`, код реле `RM35BA10`.
Точное совпадение артикула проверяется раньше разбора технических параметров. Ведущие нули сохраняются.
Отсутствие завершающего `_` допускается только как поисковый алиас; сохранённый артикул не изменяется.

Это ограниченный детерминированный разбор, не полноценное понимание произвольного текста.
Отрицания, альтернативы и диапазоны требуют уточнения/структурированных фильтров.
Оставшиеся значимые слова должны встречаться как отдельные токены.
Запрос из одного номера, которого нет в данных, не превращается в выдачу всех товаров.

**Все заданные параметры — обязательные фильтры.** При поиске 25 А товары 125 А/250 А не возвращаются.
Внутри одинаковых совпадений сортировка по необходимости проверки, затем по цене снимка и ID.
Процент «совместимости» не вычисляется и не показывается.

Ответ поиска содержит `query`, `filters`, `terms`, `total`, `count`, `products`, `data_mode`, `source_as_of`, `warnings`.
В каждом найденном товаре добавляется `match` с совпавшими полями и статусом проверки.

## 4. Важное изменение: товар 515291

В переданном detail JSON имя/описание содержат **160 А**,
а `properties.NOMINALNYY_TOK` содержит **250 А**.
Никакого решения о том, какое значение правильно, модуль не принимает.

```json
{
  "id": 515291,
  "features": {"current_a": null},
  "field_status": {"current_a": "conflict"}
}
```

Оба значения и источники сохранены в `data_conflicts`, `field_evidence`, `properties_raw`.
По точному артикулу запись доступна. При строгом фильтре 160 А эта конфликтная запись исключается.
Поэтому обычный `Legrand 160A` в этом комплекте даёт **один** результат: `515288`.

Для отдельного блока «требует уточнения»:

```python
result = catalog.search_products("Legrand 160A", include_uncertain=True)
# 515288 — совпадение по источнику; 515291 — match.status='needs_review'
```

`find_analogs(515291)` возвращает `blocked_source_conflict`, а не выбирает ток 160 или 250 наугад.
Для демонстрации предварительного сравнения без этого конфликта: `find_analogs(515290)`.
Он вернёт кандидата `515287` (оба названы 125 А, DRX250; 18/25 кА отличаются).

## 5. Нормализованные данные: что установлено, а что нет

В `data/products.normalized.json` — массив 40 объектов. Машиночитаемая схема рядом: `products.schema.json`.

- Имена, ID, артикулы, цены и ссылки перенесены из присланных данных.
- Категория — `category_path`, то есть сегменты исходного URL. Таксономия магазина не исправлялась вручную.
- Тип товара и часть характеристик извлечены правилами из имени; происхождение отмечено в `product_type_source`, `field_evidence` и `field_status`.
- Подробный технический разбор ограничен автоматами/дифавтоматами. Реле, коробки, освещение доступны по тексту/артикулу; специальные параметры этих категорий ещё не нормализованы полностью.
- `3ф` НЕ преобразуется в `poles=3`. Для `1P+N` сохраняется `pole_configuration`; число полюсов не домысливается.
- Ток контактов реле не записывается как номинальный ток автоматического выключателя.
- Числа из URL не считаются техническими характеристиками. Для `515281` сохранено расхождение имени `100А` и URL `10a` как предупреждение, без исправления исходного URL.
- `RECOMMEND` сохранён в `related_ids_raw`, но не трактуется как список взаимозаменяемых аналогов.
- `(1)`, `(20)`, `(72 шт)` не превращаются автоматически в остаток или минимальную партию.
- `KRATNOST_MIN` сохранён как `order_multiple_raw`; смысл минимального заказа/кратности должен подтвердить партнёр.
- `CML2_TAXES` не используется для пересчёта цены: база цены и налоговая логика не предоставлены.
- Валюта и единица продажи в исходной структуре не заданы: `currency=null`, `unit=null`. Не добавлять автоматически знак валюты или «шт.» без подтверждения контракта партнёром.
- `certificates=[]` + `certificate_status='not_provided_in_supplied_schema'` означает отсутствие данных в этой выборке, а не отсутствие сертификата у товара.
- Значение `source_observed_not_verified` означает наблюдение в источнике, не независимую проверку производителя.

## 6. Остатки: только снимок, не обещание продажи

У **39 товаров количество не предоставлено**: `quantity=null`, `stock_status='unknown'`.
У `515291` из присланного detail сохранены общий остаток **23** и склады.
Дата актуальности неизвестна: `source_as_of=null` у всех записей.

```python
catalog.check_stock(515291, 5, store_id=13)  # в снимке Алматы: 5
catalog.check_stock(515288, 1)               # unknown, не «0» и не «в наличии»
```

Результат содержит `snapshot_quantity`, `enough_in_snapshot`, `currently_available=null`,
`requires_live_check=true`, `cart_authorized=false`.
`store_id` — исходный ID склада, а не название города. Отсутствующий склад даёт `unknown`.
Общий `quantity` не пересчитывается суммой произвольно выбранных складов.
Для складов не предоставлены признаки разрешённой продажи/резерва, поэтому `sellable=null`.

Автопоиск при нулевом остатке запускать только если `quantity` действительно равен числу 0.
Не использовать `product.get('quantity', 0)`: отсутствие поля не доказывает отсутствие товара.
В этой выборке нет товара с подтверждённым общим нулевым остатком; для такого демо нужны дополнительные
данные партнёра или отдельно помеченная синтетическая фикстура. Синтетические остатки в эти 40 товаров не добавлены.

## 7. Кандидаты в аналоги

`find_analogs(product_id, limit=5, only_snapshot_available=False)` возвращает объект с полем `candidates`.
Это не просто похожие строки: текущие правила требуют тот же тип, известный одинаковый ток и серию.
Известные расхождения фаз/полюсов/напряжения и более низкая указанная отключающая способность исключаются.
Конфликтные записи исключаются. `None == None` никогда не добавляет «совпадение».

Каждый кандидат содержит `comparison.matching_fields`, `differences`, `missing_checks`.
Всегда `replacement_confirmed=false`, `needs_engineering_review=true` и `needs_live_stock_check=true`.
Большая цифра кА без проверки условий, напряжения, характеристик расцепителя и монтажа НЕ означает подтверждённую замену.
Это **консервативная выборка кандидатов**, а не исчерпывающий инженерный алгоритм взаимозаменяемости.
Правила для реле, светильников и других категорий не реализованы: `unsupported_category`.

`only_snapshot_available=True` исключает неизвестные/нулевые остатки, но не делает проверку актуальной.
По данному снимку такая фильтрация может не оставить кандидатов — это корректно, не ошибка.

## 8. Подключение к существующему FastAPI

Это необязательно: если backend на другом языке, используйте JSON/контракт или отдельный HTTP-сервис.

```bash
python3 -m pip install -r requirements-api.txt
```

В существующем приложении backend добавить:

```python
from ekt_catalog.api_router import router as catalog_router

# app — уже существующий объект FastAPI разработчика backend
app.include_router(catalog_router, prefix="/catalog")
```

Появятся:

```text
GET  /catalog/health
POST /catalog/search
GET  /catalog/products/{product_id}
GET  /catalog/products/{product_id}/analogs
POST /catalog/products/{product_id}/stock-check
```

Для независимой локальной проверки:

```bash
python3 -m uvicorn demo_server:app --reload
```

Открыть `http://127.0.0.1:8000/docs`.
Команда `uvicorn api:app` из предыдущих учебных шагов для этого архива **не нужна**.

```bash
curl -X POST http://127.0.0.1:8000/catalog/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"Legrand 160A","limit":5}'
```

HTTP-адаптер не содержит LLM, аутентификации пользователей, CORS-настроек или лимитов запросов.
Перед внешним доступом backend должен добавить эти механизмы. Демосервер запускается только локально.
`ValueError` фильтров превращается в 422; неизвестный ID — в 404. Неожиданные сбои не маскируются пустым результатом.

Использован обычный APIRouter по документации FastAPI:
https://fastapi.tiangolo.com/tutorial/bigger-applications/
HTTP-тесты через TestClient:
https://fastapi.tiangolo.com/tutorial/testing/

## 9. Что остаётся за интеграцией команды

Получить у партнёра точную схему авторизации и endpoint полного каталога; переданный screenshot показывал 401.
Комплект не обходит авторизацию и не подставляет выдуманный токен/endpoint списка.
Detail-ссылки из исходных карточек сохранены в `url_api_detail`.

Подключить реальные обновления цен/продаваемых остатков, документы и официальные условия покупки.
Связать LLM с функциями поиска; сложные запросы, история сессии и генерация ответа остаются отдельным слоем.
Текст карточек/описаний передавать LLM как недоверенные данные, не как инструкции.

**Корзина не входит в модуль.** Backend обязан привязывать подтверждение к конкретным ID, количеству,
варианту/складу и показанной цене. До явного подтверждения состав корзины не меняется.
После подтверждения снова проверять цену и разрешённый остаток; при изменении существенных условий
запросить новое подтверждение. Повтор одного запроса не должен дублировать добавление.
Наличие в JSON не является резервом; окончательная серверная проверка/резервирование выполняется отдельно.
Платёжные данные не собирать через этот модуль. API-ключи не передавать фронтенду и не класть в архив/Git.

## 10. Источники и воспроизводимость

`raw/page_1_user_message.json` — 20 товаров первой страницы из текста сообщения пользователя.
`raw/page_2_attachment.json` — 20 товаров второй страницы из прикреплённого TXT.
Два присланных TXT — одинаковые копии второй страницы; она импортирована один раз.
`raw/detail_515291_user_message.json` — детальная запись из более раннего сообщения.
Это 40 уникальных ID, не весь каталог EKT. `count=20` на странице не трактуется как общий размер каталога.
`raw/manifest.json` содержит происхождение и контрольные суммы источников.

Обогащение записи: данные detail добавляются к list-записи; это не утверждение, что detail новее.
У `515291` изображения в list/detail различаются; для отображения явно выбран image из detail, оба источника сохранены.
`build_catalog.py` прекращает сборку при расхождении имени, артикула, цены или количества между list/detail,
когда поле есть в обоих источниках. Конфликты характеристик внутри detail сохраняются нормализатором.
Даты актуальности не выдумываются; дата сборки архива не является датой остатков.

Пересоздать JSON из прилагаемых raw-снимков:

```bash
python3 build_catalog.py
python3 -m unittest discover -s tests -v
```

Для будущей интеграции `normalize_product(raw_record)` доступна отдельно.
Не перезаписывать конфликтующие снимки молча: сохранять происхождение и явно выбирать стратегию обновления.
